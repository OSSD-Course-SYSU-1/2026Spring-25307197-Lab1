# 分布式待办数据同步使用指南

## 功能说明

本应用已集成分布式待办数据同步功能,支持跨设备实时同步待办数据。当用户在任一设备上添加、修改或删除待办时,数据会自动同步到同一账号下的其他设备。

## 技术实现

### 1. 分布式数据对象 (Distributed Data Object)

使用HarmonyOS的分布式数据对象实现跨设备数据同步,具有以下特点:
- **实时同步**: 数据变更自动同步到其他设备
- **简单易用**: 像操作本地对象一样操作分布式对象
- **自动冲突解决**: 系统自动处理数据冲突

### 2. 核心代码结构

#### 初始化分布式数据对象

```typescript
// 在EntryAbility.ets中
private initDistributedTodoObject(): void {
  // 创建分布式数据对象
  this.todoDataObject = distributedDataObject.create(this.context, initData);
  
  // 设置sessionId (同一应用使用相同sessionId)
  const sessionId = 'todo_sync_session_' + this.context.applicationInfo.name;
  this.todoDataObject.setSessionId(sessionId);
  
  // 注册数据变更监听
  this.todoDataObject.on('change', (sessionId, fields) => {
    // 处理接收到的数据
    this.handleReceivedTodoData(action, todoId, todoData, deviceId);
  });
}
```

#### 发送待办数据

```typescript
// 发送新增待办
public sendTodoData(action: string, todoId: string, todoData?: string): void {
  // 更新分布式对象,自动同步
  this.todoDataObject['action'] = action;
  this.todoDataObject['todoId'] = todoId;
  this.todoDataObject['todoData'] = todoData || '';
  this.todoDataObject['timestamp'] = Date.now();
  this.todoDataObject['deviceId'] = deviceId;
}
```

## 使用方法

### 1. 前置条件

确保以下条件满足:
- ✅ 所有设备登录同一华为账号
- ✅ 所有设备处于同一网络(Wi-Fi)或蓝牙范围内
- ✅ 已授予分布式数据同步权限

### 2. 权限配置

已在 `module.json5` 中配置以下权限:

```json
{
  "requestPermissions": [
    {
      "name": "ohos.permission.DISTRIBUTED_DATASYNC",
      "reason": "$string:distributed_datasync_reason",
      "usedScene": {
        "abilities": ["EntryAbility"],
        "when": "inuse"
      }
    },
    {
      "name": "ohos.permission.GET_DISTRIBUTED_DEVICE_INFO",
      "reason": "$string:get_distributed_device_info_reason",
      "usedScene": {
        "abilities": ["EntryAbility"],
        "when": "inuse"
      }
    }
  ]
}
```

### 3. 发送待办数据示例

在需要发送待办数据的地方调用:

```typescript
// 获取EntryAbility实例
let ability = getContext(this) as common.UIAbilityContext;

// 发送新增待办
const todoItem = {
  id: '123',
  title: '完成分布式功能开发',
  date: new Date(),
  priority: 1
};
ability.sendTodoData('add', todoItem.id, JSON.stringify(todoItem));

// 发送更新待办
ability.sendTodoData('update', todoItem.id, JSON.stringify(todoItem));

// 发送删除待办
ability.sendTodoData('delete', todoItem.id);
```

### 4. 接收待办数据

数据接收已自动处理,在 `handleReceivedTodoData` 方法中:

```typescript
private handleReceivedTodoData(action, todoId, todoData, deviceId): void {
  if (action === 'add') {
    // 新增待办
    const todoItem = JSON.parse(todoData);
    this.dataManager.addTask(todoItem);
  } else if (action === 'update') {
    // 更新待办
    const todoItem = JSON.parse(todoData);
    this.dataManager.updateTask(todoItem);
  } else if (action === 'delete') {
    // 删除待办
    this.dataManager.deleteTask(todoId);
  }
}
```

## 数据流程

```
设备A (发送方)                分布式软总线                设备B (接收方)
     |                            |                            |
     | 1. 用户添加待办             |                            |
     |----------------------------|                            |
     | 2. 调用sendTodoData       |                            |
     |----------------------------|                            |
     | 3. 更新分布式对象          |                            |
     |----------------------------|---------------------------->
     |                            | 4. 数据自动同步             |
     |                            |----------------------------|
     |                            | 5. 触发change事件          |
     |                            |----------------------------|
     |                            | 6. 调用handleReceivedTodoData
     |                            |----------------------------|
     |                            | 7. 更新本地数据             |
     |                            |----------------------------|
     |                            | 8. 保存到持久化存储         |
```

## 注意事项

### 1. 数据大小限制
- 单个分布式数据对象大小不超过500KB
- 建议单条待办数据不超过10KB

### 2. 设备数量限制
- 最多支持3台设备同时协同
- 单个应用最多创建16个分布式数据对象实例

### 3. 同步延迟
- 设备A修改数据后,设备B通常在50ms内收到变更通知
- 网络状况不佳时可能延迟更长

### 4. 冲突处理
- 系统采用"最后写入获胜"(LWW)策略
- 建议在待办数据中包含时间戳字段

### 5. 生命周期管理
- 应用进入后台时,分布式对象仍然工作
- 应用退出时,自动释放分布式对象资源

### 3. 常见问题

**问题1: 数据未同步**
- 检查设备是否登录同一账号
- 检查设备是否在同一网络
- 检查权限是否已授予

**问题2: 同步延迟高**
- 检查网络连接质量
- 减少数据大小
- 避免频繁更新

**问题3: 数据冲突**
- 使用时间戳字段
- 实现自定义冲突解决逻辑

## 性能优化建议

### 1. 数据压缩
对于大量待办数据,建议压缩后再发送:

```typescript
// 使用JSON序列化时,移除不必要的字段
const minimalData = {
  id: todo.id,
  title: todo.title,
  date: todo.date.getTime() // 转换为时间戳
};
```

### 2. 批量操作
对于批量操作,建议合并为一次发送:

```typescript
// 批量新增
const batchData = todos.map(t => ({...t}));
ability.sendTodoData('batchAdd', 'batch', JSON.stringify(batchData));
```

### 3. 增量同步
只同步变更的字段,减少数据传输量:

```typescript
// 只更新标题
const updateData = { id: todoId, title: newTitle };
ability.sendTodoData('partialUpdate', todoId, JSON.stringify(updateData));
```

## 扩展功能

### 1. 离线支持
结合本地持久化存储,实现离线编辑,上线后自动同步:

```typescript
// 保存到本地队列
if (!isOnline) {
  offlineQueue.push({action, todoId, todoData});
} else {
  ability.sendTodoData(action, todoId, todoData);
}

// 上线后同步队列
onDeviceOnline() {
  offlineQueue.forEach(item => {
    ability.sendTodoData(item.action, item.todoId, item.todoData);
  });
  offlineQueue.clear();
}
```

### 2. 数据版本控制
添加版本字段,实现更精细的冲突控制:

```typescript
interface VersionedTodo {
  id: string;
  version: number;
  data: any;
}

// 更新时检查版本
if (localVersion < remoteVersion) {
  // 使用远程数据
} else {
  // 保留本地数据
}
```

### 3. 同步状态提示
在UI中显示同步状态,提升用户体验:

```typescript
@State syncStatus: string = '已同步';

// 监听同步状态
todoDataObject.on('status', (sessionId, networkId, status) => {
  if (status === 'online') {
    this.syncStatus = '同步中...';
  } else {
    this.syncStatus = '已同步';
  }
});
```
