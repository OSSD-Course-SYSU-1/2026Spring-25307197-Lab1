# 分布式流转功能说明

## 📋 功能概述

本项目已完整实现「流转至其他设备」功能，支持将当前应用状态无缝迁移到其他HarmonyOS设备。

## ✅ 已完成的功能

### 1. 右上角菜单按钮
- **位置**: `MainEntry.ets` 第186-192行
- **功能**: 在Navigation组件的右上角添加「流转至其他设备」菜单项
- **触发**: 点击后弹出设备选择弹窗

### 2. 设备选择弹窗
- **文件**: `DeviceSelectDialog.ets`
- **功能**:
  - 自动获取并显示在线设备列表
  - 过滤掉本地设备
  - 显示设备名称、类型和状态
  - 支持重新搜索设备

### 3. 在线设备获取
- **实现**: 使用 `distributedDeviceManager` API
- **功能**:
  - 创建设备管理器实例
  - 获取可用设备列表
  - 监听设备上下线状态

### 4. 页面状态缓存
- **文件**: `DistributedTransferUtil.ets`
- **缓存内容**:
  - 当前Tab索引
  - 窗口尺寸
  - 时间戳

### 5. 应用接续功能
- **文件**: `EntryAbility.ets`
- **实现**:
  - `onContinue()`: 保存迁移数据
  - `handleContinuation()`: 恢复页面状态
  - `setMissionContinueState()`: 设置迁移状态为ACTIVE

## 🔧 配置要求

### module.json5 配置

```json5
{
  "module": {
    "abilities": [
      {
        "name": "EntryAbility",
        "continuable": true  // 启用应用接续能力
      }
    ],
    "requestPermissions": [
      {
        "name": "ohos.permission.DISTRIBUTED_DATASYNC",  // 分布式数据同步权限
        "reason": "$string:distributed_datasync_reason",
        "usedScene": {
          "abilities": ["EntryAbility"],
          "when": "inuse"
        }
      }
    ]
  }
}
```

## 📱 使用流程

### 用户操作流程

1. **打开应用** - 在源设备上打开应用
2. **点击菜单** - 点击右上角「流转至其他设备」菜单
3. **选择设备** - 在弹窗中选择目标设备
4. **查看提示** - 应用提示"已准备流转至 XXX，请从屏幕右上角下滑打开超级终端面板完成流转"
5. **打开超级终端** - 从屏幕右上角下滑打开超级终端面板
6. **完成流转** - 点击目标设备图标，系统自动完成流转

### 技术实现流程

```
用户点击菜单
    ↓
显示设备选择弹窗
    ↓
获取在线设备列表 (distributedDeviceManager.getAvailableDeviceListSync)
    ↓
用户选择目标设备
    ↓
缓存页面状态 (DistributedTransferUtil.cachePageState)
    ↓
提示用户使用超级终端面板
    ↓
用户通过超级终端面板触发流转
    ↓
系统调用 onContinue() 方法
    ↓
保存迁移数据到 wantParam
    ↓
目标设备接收数据
    ↓
系统调用 onCreate() 或 onNewWant()
    ↓
恢复页面状态 (restoreWindowStage)
```

## ⚠️ 重要说明

### 为什么不能直接触发流转？

`distributedMissionManager.continueMission` 是**系统级API**，需要 `ohos.permission.MANAGE_MISSIONS` 权限，该权限仅授予系统应用。三方应用无法直接调用此API发起流转。

### 解决方案

HarmonyOS提供了**应用接续（Continuation）**机制：
- 应用通过 `onContinue()` 保存迁移数据
- 用户通过**系统超级终端面板**触发流转
- 系统自动完成设备间迁移
- 目标设备通过 `onCreate()/onNewWant()` 恢复数据
