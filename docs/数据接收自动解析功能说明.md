# 待办数据接收自动解析功能说明

## 功能概述

本功能实现了接收待办数据后自动解析并插入本地待办列表，自动保存到数据库的完整流程。

## 核心组件

### 1. TodoDataReceiver（数据接收管理器）

位置：`commons/common_lib/src/main/ets/utils/TodoDataReceiver.ets`

**主要功能：**
- JSON数据解析和验证
- 数据格式校验
- TodoItem对象转换
- 批量数据处理

**使用示例：**

```typescript
import { TodoDataReceiver, TodoAction } from '@ohos_agcit/daily_schedule_common_lib';

// 获取实例
const receiver = TodoDataReceiver.instance;

// 解析待办数据
const jsonData = '{"title":"完成报告","planTime":1717660800000,"priorityType":2}';
const data = receiver.parseAndValidate(jsonData);

if (data) {
  // 转换为TodoItem对象
  const todoItem = receiver.convertToTodoItem(data, true);
  console.log('待办创建成功:', todoItem.title);
}
```

### 2. EntryAbility（分布式数据接收）

位置：`products/phone/src/main/ets/entryability/EntryAbility.ets`

**数据接收流程：**

```
其他设备发送数据 
  ↓
分布式数据对象变更监听
  ↓
handleReceivedTodoData() 处理
  ↓
TodoDataReceiver 解析验证
  ↓
TodoDataManager 更新数据
  ↓
TodoPersistenceWrapper 自动保存到数据库
```

## 数据格式

### 待办数据结构

```typescript
interface TodoDataFormat {
  taskID?: string;          // 任务ID（可选，新增时自动生成）
  title?: string;           // 待办标题
  planTime?: number;        // 计划时间（时间戳）
  repetitionType?: number;  // 重复类型（0-3）
  reminderType?: number;    // 提醒类型（0-4）
  priorityType?: number;    // 优先级（0-3）
  isFinished?: boolean;     // 是否完成
}
```

### 操作类型

```typescript
enum TodoAction {
  ADD = 'add',      // 新增待办
  UPDATE = 'update', // 更新待办
  DELETE = 'delete'  // 删除待办
}
```

## 数据验证规则

### 必填字段验证
- **title**: 不能为空字符串（新增操作时）

### 数值范围验证
- **priorityType**: 0-3（无、低、中、高）
- **repetitionType**: 0-3（不重复、每天、工作日、自定义）
- **reminderType**: 0-4（不提醒、提前1天、提前2天、提前3天、提前1周）

### 时间格式验证
- **planTime**: 必须是有效的正数时间戳

## 使用场景

### 场景1：分布式设备间同步

当设备A向设备B发送待办数据时：

```typescript
// 设备A发送
const todoItem = new TodoItem(...);
const syncPacket = {
  action: 'add',
  todoId: todoItem.taskID,
  todoData: JSON.stringify({
    title: todoItem.title,
    planTime: todoItem.planTime.getTime(),
    priorityType: todoItem.priorityType
  }),
  timestamp: Date.now(),
  deviceId: 'device_A'
};

// 设备B自动接收并处理
// EntryAbility的handleReceivedTodoData会自动：
// 1. 解析JSON数据
// 2. 验证数据格式
// 3. 创建TodoItem对象
// 4. 添加到本地待办列表
// 5. 保存到数据库
```

### 场景2：批量导入待办

```typescript
const receiver = TodoDataReceiver.instance;

// 批量解析待办数据
const todoDataArray = [
  '{"title":"任务1","planTime":1717660800000}',
  '{"title":"任务2","planTime":1717747200000}',
  '{"title":"任务3","planTime":1717833600000}'
];

const results = receiver.batchParse(todoDataArray);

// 处理解析结果
results.forEach((result, index) => {
  if (result.success && result.todoItem) {
    // 添加到数据管理器
    TodoDataManager.instance.addTask(result.todoItem);
    console.log(`待办${index + 1}导入成功`);
  } else {
    console.log(`待办${index + 1}导入失败: ${result.message}`);
  }
});
```

### 场景3：网络数据接收

当从服务器获取待办数据时：

```typescript
// 假设从API获取的数据
const serverData = await fetchTodoListFromServer();

serverData.forEach(item => {
  // 使用TodoDataReceiver解析
  const data = receiver.parseAndValidate(JSON.stringify(item));
  
  if (data) {
    const todoItem = receiver.convertToTodoItem(data, true);
    TodoDataManager.instance.addTask(todoItem);
  }
});

// 自动保存到数据库
TodoPersistenceWrapper.save();
```

## 自动保存机制

### 触发保存的时机

1. **数据变更时**：TodoDataManager的数据变更会触发TodoPersistenceWrapper的自动保存
2. **应用进入后台**：EntryAbility的onBackground()会立即保存数据
3. **接收远程数据后**：handleReceivedTodoData处理完成后立即保存

### 保存策略

- **延迟保存**：使用500ms延迟，避免频繁写入
- **立即保存**：关键操作（如应用进入后台）立即保存
- **自动监听**：每秒检查数据变化并触发保存

## 日志追踪

系统会输出详细的日志信息，便于调试：

```
[DistributedTodo] 开始处理待办数据: action=add, todoId=xxx, from=device_B
[DistributedTodo] 新增待办: 完成报告, 计划时间: 2024-06-06, 优先级: 2
[DistributedTodo] ✓ 待办添加成功，已自动保存到数据库
```

错误日志示例：

```
[DistributedTodo] ✗ 数据验证失败，无法添加待办
[TodoDataReceiver] 验证失败：优先级超出范围
```

## 性能优化

1. **数据验证前置**：在解析阶段就进行数据验证，避免无效数据进入系统
2. **批量处理**：支持批量解析和处理，提高效率
3. **异步保存**：数据保存采用异步方式，不阻塞主线程
4. **延迟保存策略**：减少频繁的数据库写入操作

## 注意事项

1. **数据完整性**：接收的数据必须包含至少一个有效字段
2. **时间格式**：时间必须使用时间戳（毫秒）格式
3. **ID生成**：新增待办时建议让系统自动生成taskID
4. **错误处理**：所有操作都有完善的错误处理和日志记录
